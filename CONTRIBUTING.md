# Contributing to SEDSVIT Website

Thanks for your interest in contributing! This guide will help you get set up and productive quickly.

## Prerequisites

| Requirement | Version      |
| :---------- | :----------- |
| **Node.js** | `>= 22.12.0` |
| **pnpm**    | `12.3.4`     |

pnpm is the project's package manager. You don't need to install it globally — it is declared in `devEngines` inside `package.json`, so your environment will download it automatically if it's missing.

## About Vite+ (`vp`)

This project uses **[Vite+](https://viteplus.dev)** (command: `vp`) as its unified toolchain for formatting, linting, type-checking, dependency management, and Git hooks. Under the hood **vp delegates to pnpm** for all package-management operations, so you can think of `vp install` as a pnpm-powered command with extra superpowers.

You should prefer `vp` over raw `pnpm` / `npx` calls for everything it covers — formatting, linting, checking, installing, and staged-file hooks.

## Getting Started

```bash
# 1. Clone the repository
git clone <repo-url>
cd sedsvit-website

# 2. Install dependencies (vp uses pnpm under the hood)
vp install

# 3. Set up Git hooks and agent integration (runs automatically via the "prepare" script)
vp config

# 4. Start the dev server
vp run dev
```

> Use `vp` for everything (dev, install, format, lint, check, staged).

## Common Commands

All commands are run from the project root.

### Development

| Command          | Action                                                |
| :--------------- | :---------------------------------------------------- |
| `vp install`     | Install dependencies (uses pnpm under the hood)       |
| `vp run dev`     | Start the local dev server (`localhost:4321`)         |
| `vp run build`   | Build the production site to `./dist/`                |
| `vp run preview` | Preview the production build locally before deploying |

### Code Quality (use `vp`)

| Command          | Action                                                            |
| :--------------- | :---------------------------------------------------------------- |
| `vp fmt`         | Format all source files (in place)                                |
| `vp fmt --check` | Check formatting without writing changes                          |
| `vp lint`        | Lint all source files                                             |
| `vp check`       | Run formatting, linting, **and** type checks together             |
| `vp check --fix` | Auto-fix formatting and lint issues                               |
| `vp staged`      | Run the staged-file linters (same thing the pre-commit hook runs) |

### Adding Dependencies

```bash
# Production dependency
vp install <package>

# Dev dependency
vp install -D <package>
```

Because `vp install` delegates to pnpm, all standard pnpm flags work after `--`:

```bash
vp install some-package -- --save-exact
```

## Code Style

Formatting and linting are configured in `vite.config.ts` via Vite+:

- **Quotes:** single quotes (`'`), including JSX single quotes
- **Semicolons:** yes
- **Indentation:** 4 spaces
- **Imports:** sorted automatically by the formatter

Run `vp fmt` (or `vp check --fix`) before committing to make sure your code matches the project style.

## Git Hooks

The project uses Vite+ Git hooks (managed via `.vite-hooks/`):

- **`prepare` script** → runs `vp config` to install the hook dispatcher. This happens automatically after `vp install`.
- **`pre-commit` hook** → runs `vp staged`, which executes the `staged` config from `vite.config.ts`:
    ```ts
    staged: {
        '*': 'vp check --fix',
    }
    ```
    This means every commit is automatically formatted, linted, and type-checked. If issues are found they are fixed in place and you may need to re-stage the changes before committing.

## Tips

- **TypeScript is strict.** The `tsconfig.json` extends `astro/tsconfigs/strict` — expect the compiler to catch most issues early.
- **Astro routing is file-based.** Any `.astro` or `.md` file in `src/pages/` becomes a route based on its file name.
- **Static assets** (images, fonts referenced by URL) go in `public/`. Assets imported in code (fonts, images bundled at build time) go in `src/assets/`.
- **Environment variables** must be prefixed with `VITE_` to be exposed to client-side code. Never commit `.env` files — only `.env.example` is tracked.
